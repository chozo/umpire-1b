# 一塁塁審ジャッジ

プレイヤーは野球の一塁塁審。内野ゴロで、**打者走者の足がベースに触れるのと、送球が一塁手のミットに収まるのと、どちらが先か**を見極めて「アウト」「セーフ」をコールする 3D のブラウザゲームです（縦型 9:16、スマホ向け。PC でも遊べます）。

**公開URL: https://game.chozo.net/umpire-1b/**

## 遊び方

- 打者が打つと、塁審の目線が打球を追い、送球が来る前に一塁ベースへ向き直る
  - 判定の位置は、一塁ベースの先（ライト側）から少しフェア側へ回り込んだところ。ベースを踏む足とミットの真ん中を見て、画角を絞る（`src/config.ts` の `CAMERA`）。高い送球でもミットが画面の端に寄らず、走者の体にボールが隠れない
- 足がベースに触れ、ボールがミットに収まったら（両方が起きたら）**2秒以内**にコールする
  - スマホ: 画面下の「セーフ」（左）「アウト」（右）
  - PC: <kbd>F</kbd>（または ←）= セーフ、<kbd>J</kbd>（または →）= アウト、<kbd>M</kbd> = BGM（ボタンの並びと同じ）
  - 両方が起きる前の入力は「まだ早い！」として無視する
- **誤審（時間切れを含む）が3回で失格**。それまでプレーは続く

## 判定のルール

- **ボールがミットに収まるのが先ならアウト、足がベースに触れるのが先ならセーフ**
- 正解は、プレーを作るときに決めた2つの時刻の差 `margin = 足がベースに触れる時刻 − 捕球の時刻` で決まる（正ならアウト）
- 差はいつも 0.001 秒以上あり、同時にはならない
- 画面の動き・音・リプレイは、すべて同じ時刻と位置のデータから作っている（`src/play.ts`）
  - 走者の歩幅は「ベースを踏む一歩」から逆算して並べ、その一歩の着地の瞬間を到達時刻にしている
  - 走るフォーム: 肘を曲げて腕を大きく振り（前の手は胸の高さ、後ろの手は腰の後ろ）、足は離れてすぐかかとを蹴り上げる。ベースを踏む一歩では上体を前に倒し、腰を落としてベースを見る。走者の靴は赤で、ベースの上で一塁手の黒い靴と見分けられる
  - 一塁手のグラブは捕球点にぴったり合わせて伸ばす（手足は IK で動かしている）
  - プレー中の音は、起きる時刻の少し前に「何秒後に鳴らすか」を予約する。画面のコマ（1/60 秒）のずれが音に入らない

## 難易度

| プレー | 内容 |
|---|---|
| 1〜3人目 | 練習。差 0.3 秒以上のはっきりしたタイミングだけ。2・3人目は直前と逆の結果 |
| 4人目〜 | 際どい・中くらい・はっきりが混ざる。際どさの範囲と割合は、そのゲームでの正解数で変わる（下の「段階と称号」） |
| 9人目〜 | 左打者が登場（一塁に近く、少し速い） |
| 16人目〜 | 送球がそれ、一塁手が低く・高く・横に大きく伸びる |

- 打球を処理する野手は 遊撃手・二塁手・三塁手・投手 から選ぶ。送球の距離と速さ、打球の速さ、送球までの持ち替えの時間を、決めた差に合うように組み合わせる
- 打球の種類（`src/play.ts` の `GroundKind`）: ふつうのゴロ（約 40%）、横への打球（三遊間・二遊間など、横に 2.5〜4.8m、約 35%）、遅いゴロ（前に 3〜7m 突っ込む、打球の平均 7〜16 m/s、約 25%）。投手ゴロ（全体の約 4%）はボテボテの当たり
- 野手の動き（`src/actors.ts`）
  - 打った瞬間に全員が小さく跳んで構え直す（スプリットステップ）
  - 捕る野手: ふつう・横の打球は、すぐに全力で打球の正面に入り、構えて待つ。遅いゴロと投手ゴロは、構えて待ってから、捕る瞬間に間に合うように加速しながら突っ込み、走りながら捕る
  - ほかの内野手: 遊撃手・三塁手の打球は二塁手が、二塁手・投手の打球は遊撃手が二塁ベースのカバーに走る。残りは打球の方へ数歩出る
  - 外野手: 打球の方へ最大 5m 前進してカバーに入る
- 得点（「球審ジャッジ」と同じ形。`src/config.ts` の `SCORE`）: 正解 100 点、際どいプレーの正解 300 点。足とボールの両方が起きてから 0.7 秒以内にコールすると +20 点、1.0 秒以内なら +10 点の早押しボーナス
  - 表示も「球審ジャッジ」と同じ。ふつうの正解は緑の「正解」、際どいプレーの正解はオレンジ〜赤の「ナイスジャッジ！」で、下に内訳（例「300 ＋ 20（早押しボーナス）」）。誤審は赤の「誤審…」、時間切れは「時間切れ」

## 段階と称号

そのゲームでここまでに正しく判定できた数（練習を含む）で段階が決まる（`src/config.ts` の `LEVELS`）。段階ごとに、出てくる差のいちばん小さい値、際どいとする差の境目、際どいプレーが出る確率が変わる。際どいプレー（差が境目以下）は必ずリクエストされ、リプレイになる。ゲームオーバーの結果画面には、最後の正解数の段階の称号を出す（基準は「球審ジャッジ」と同じ）。

| 正解数 | 称号 | 差の範囲（いちばん小さい差〜際どいの境目） | 際どいプレーが出る確率 |
|---|---|---|---|
| 0〜9 | 草野球の審判 | 0.03〜0.05 秒 | 40% |
| 10〜19 | 審判見習い | 0.02〜0.04 秒 | 50% |
| 20〜29 | 二軍の審判 | 0.01〜0.03 秒 | 50% |
| 30〜39 | 一軍の審判 | 0.005〜0.02 秒 | 60% |
| 40〜49 | ？？？ | 0.001〜0.015 秒 | 60% |
| 50〜99 | ？？？ | 0.001〜0.01 秒 | 60% |
| 100以上 | ？？？ | 0.001〜0.01 秒 | 60% |

正解 40 回以上の称号はシークレット（遊んで確かめてほしいので、ここには書かない）。

- 例: 正解 0〜9 回のときは、差が 0.03 秒より小さいプレーは出さない。差が 0.05 秒以下なら際どいプレーで、全体の 40% の確率で出る
- 際どくないプレーは境目より大きい差。中くらい（境目のすぐ上から 0.06 秒の幅）が 35%、残りははっきり（中くらいの上限か 0.10 秒の大きいほうから 0.2 秒の幅）。例: 正解 0〜9 回なら 中くらい 0.051〜0.11 秒、はっきり 0.11〜0.31 秒
- 練習の3プレーは段階によらず、差 0.3 秒以上

## 監督のリクエストとリプレイ

- 次のときは、判定に不満な側の監督がベンチから出てきて、両手で四角（モニター）を描いてリクエストする
  - 誤審のとき（必ず）
  - 際どい判定のとき（正しくても必ず）。リプレイになる割合は上の「際どいプレーの割合」と誤審の分
  - アウトとコールしたら攻撃側（三塁側ベンチ）、セーフとコールしたら守備側（一塁側ベンチ）の監督
- リクエストの後は、正誤を明かさずにリプレイで検証する
  1. 塁審の目線のスロー（0.4 倍）
  2. 上下2画面のスーパースロー。上は足とベース、下は送球とミット。それぞれの瞬間で止め、最初の出来事からの時間（秒）を出す
  3. 結果: 正しい判定と差（「ボールが 0.012 秒 先」など）、「判定どおり」か「判定がくつがえった（誤審）」か
- 監督のリクエストの場面からリプレイの途中まで、タップ（PC は Space / Enter / F / J）でスローを飛ばして結果だけを出せる（その場面が始まって 0.4 秒は押し間違い防止のため無視）

## 音

すべて Web Audio API で合成しています（音声ファイルなし）。

| 音 | 鳴るとき |
|---|---|
| 打球音（カキーン） | 打つ瞬間 |
| 走者の足音 | 走者の足が地面に着くたび（塁審からの距離で大きさと左右が変わる）。ベースを踏む一歩も同じ音・同じ大きさにして、音だけで捕球との前後が分からないようにしている |
| ベースを踏む音（ドスッ） | リプレイの上下2画面で、足がベースに触れた瞬間に止まるときだけ |
| 内野手の捕球音 | ゴロをグラブで捕る瞬間 |
| 送球の風切り音 | ミットに届く直前 |
| 一塁手の捕球音（パシッ） | ミットに収まる瞬間 |
| コールの効果音 | アウト／セーフをコールしたとき |
| 観客の歓声・どよめき・ブーイング | コール・リクエスト・リプレイの結果 |
| 場内アナウンスのチャイム | リクエストのとき |
| 応援風の BGM | 「球審ジャッジ」と同じ自作の曲。プレー中は足音が聞こえるよう小さくし、リプレイ中はスロー再生 |

リプレイの瞬間（足・ミット）では、音程を下げたスローの音を鳴らします。

## 構成

```text
app/
├── index.html
├── public/            # favicon.svg と ogp.png（SNS共有用 1200×630）
├── src/
│   ├── config.ts    # 調整値（寸法・走る速さ・野手の位置・難易度・得点）
│   ├── play.ts      # 1プレーの正解（時刻と位置）を作る。描画に依存しない
│   ├── figure.ts    # ローポリの人形（手足の先の位置から IK で関節を決める）
│   ├── actors.ts    # 打者走者・野手・一塁手・投手・監督の動き（時刻 t の関数）
│   ├── camera.ts    # 塁審の目線、リプレイのカメラ、監督のアップ
│   ├── scene.ts     # スタジアム、ボール、リプレイの印、リクエストの四角の軌跡
│   ├── audio.ts     # 効果音と BGM の合成
│   ├── main.ts      # 進行・入力・表示・確認用の入口（window.__game）
│   └── style.css
├── tests/play.test.ts  # プレー生成の単体テスト（vitest）
└── tools/
    ├── e2e.mjs         # ブラウザでの通し確認（playwright-core + インストール済み Chrome）
    ├── shots.mjs       # 1プレーの各時点のスクリーンショット（見た目の確認用）
    ├── contact.mjs     # スクリーンショットを1枚に並べる
    ├── ogp/make-ogp.mjs # OGP画像 public/ogp.png を作る
    └── promo/          # 告知動画の撮影と台本（scenario.js）。出力は ../video/
```

## 開発

```bash
npm install
npm run dev        # http://localhost:5289/
npm test           # 単体テスト
npm run e2e        # 通し確認（npm run dev を起動した状態で）
npm run build      # dist/ を空にして、型チェック + dist/umpire-1b/ へ出力
npm run ogp        # OGP画像を作り直す（npm run dev を起動した状態で）
npm run promo      # 告知動画を作る（ビルドしてから撮影。出力は ../video/）
npm run deploy     # ビルドして Cloudflare Workers へ公開
```

## 告知動画

`npm run promo` で、縦型（1080×1920、30fps）の約 28 秒の動画を作る。実際のゲーム画面をヘッドレスの Chrome で1コマずつ撮り、字幕と効果を重ねて MP4 にする（`tools/promo/`、台本は `tools/promo/scenario.js`）。

- 出力: `../video/umpire-1b-promo.mp4`、表紙 `umpire-1b-promo-cover.jpg`、2秒おきの一覧 `umpire-1b-promo-sheet.jpg`（動画はリポジトリに含めない）
- 構成: つかみ（0.03 秒差のスーパースロー「どっちが先！？」）→ タイトル → ふつうのプレーで「セーフ！」→ 際どいプレーで「アウト！」→ 監督のリクエスト → スーパースロー → ナイスジャッジ！ → 「正解するほど際どくなる！」「きみの目で見極めろ！」→ エンドカード（称号の名前はシークレットなので動画には出さない）
- 際どいプレーはわざと 0.03 秒前後にしている（つかみ 0.030 秒、リクエストのプレー 0.027 秒）。遊ぶと、それよりずっと厳しい差を判定させられる理不尽さを楽しんでもらうため
- 配置: ゲーム画面を真ん中に大きく置く（横の中心 50%、高さの 86%）。字幕とエンドカードも真ん中
- 音: ゲームの効果音と応援風の BGM を、撮影中は鳴らさずに記録し（`window.__game.audio` の `capture` / `drain`）、書き出しで同じ関数（`render`）を使って OfflineAudioContext で鳴らし直す。撮らずに進めた区間のあとは `resync` で BGM の状態を記録し直す。音量は -14.2 LUFS、真のピーク -1.9 dBTP
- 確認用: `PROMO_EVERY=15 npm run promo` で 15 コマおきの一覧だけ作る。`PROMO_ENCODE_ONLY=1 npm run promo` で撮り直さずに書き出しだけやり直す
